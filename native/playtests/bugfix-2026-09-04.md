## Additional critical finding: full server restart loses native sessions

The native server's `WebSocketServer::sessions_` owns ProtocolSession instances
in memory. `WebSocketServer::stop()` clears them, and a login with an unknown
identity constructs a fresh session. `native/src/server_main.cpp` does not
load or save them to disk. The owner launcher stops that server when the game
closes. Existing reconnect and succession checks retain the server/session
object and do not establish persistence across a new server process.

The next persistence pass must restore the exact House, Scion, oath, inventory,
worn items, currency, quests, tree, and item progression after stopping and
restarting the actual server executable. It needs a real process-restart
regression, atomic durable writes, and an explicit save location. This pass
does not implement that storage boundary.
